### FAQ anchors

- **Every question (64) and section (10) on `/faq/` now carries a stable `id`**
  slugified from its own text, with a `#` permalink beside the heading.
  Generated by a one-time transform over `src/components/FAQ.astro` rather than
  by hand, with a collision check — none, including the near-miss pair "How does
  Hipo _choose_ validators?" / "How does Hipo _select_ validators?" in different
  sections.
- **The id sits on the wrapper `div`, not the heading**, so following a link
  brings the question and its answer into view together rather than scrolling
  the answer off the top. `scroll-mt-8` on both wrapper utilities keeps the
  target off the viewport edge.
- **The `#` is faintly visible (40% `purple9`) rather than hover-only.** The
  common pattern reveals it on hover, which leaves the anchors unreachable on
  touch devices.
- Slugs derive from question text, so they are self-documenting and survive
  reordering — but they break if a question is _reworded_. That is the trade
  against short hand-picked slugs.
- Added the `hipo-faq-anchor` utility to `src/styles/global.css`.

### Cutover runbook

Added to `specs/gitbook-docs-migration.md`, replacing the three-bullet sketch:

- **Corrected a wrong premise.** The original section read the Cloudflare
  response headers (`server`, `cf-ray`) as evidence that `docs.hipo.finance`
  already passed through the `hipo.finance` zone. It does not — those are
  GitBook's own Cloudflare. The record is a **DNS-only** CNAME to
  `ae2b5f05a4-hosting.gitbook.io`, so traffic never reaches the zone's edge and
  **no Redirect Rule can fire until it is proxied**. That flip, not the rule
  creation, is the cutover moment.
- **The zone's plan does not support regex functions**, so the runbook uses
  wildcard pattern matching. Nested `regex_replace()` is rejected on any plan;
  a single-pass `([.]md)?/?$` alternative was worked out but is unusable here.
- Five ordered rules (intro page, root, `.md`, trailing slash, catch-all), each
  with its rationale and which to drop first under a rule-count limit; plus
  Always Use HTTPS, the DNS flip, a verification script, and cleanup.
