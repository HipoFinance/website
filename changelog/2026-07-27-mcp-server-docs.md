### What the MCP server is

`HipoFinance/mcp` (MIT, published as `@hipo-finance/mcp`) is a Model Context
Protocol server that exposes Hipo to AI clients. It has two halves:

- **Nine tools** backed by contract getters through `@hipo-finance/sdk` and a
  `TonClient` against toncenter — exchange rate and APY, treasury state, round
  timing, fees, wallet status, reward history, participations, loan info, and
  max punishment. `src/reader.ts` is the only place that touches the chain, and
  `src/protocol.ts` only formats what the getters return; nothing re-implements
  protocol math.
- **Five documentation resources** (`hipo://docs/*`) proxied from the contract
  repository's raw markdown plus this site's `llms.txt`, cached for 300s with
  stale-on-error fallback.

It ships both transports: `dist/stdio.js` for local clients and a stateless
Express streamable-HTTP server (`dist/http.js`) for the hosted deployment.
It is strictly read-only — no keys, no signing, no outbound messages.

### The page

`src/content/docs/hipo-mcp-server.md`, served at `/docs/hipo-mcp-server/`, with
a top-level sidebar entry `🤖 Hipo MCP Server` added to `astro.config.mjs`
immediately before `🎨 Brand Kit`. Docs pages are not autogenerated, so the
sidebar entry is required for the page to be reachable.

The page is written for the docs audience rather than as a README copy:

- It leads with what a user gets out of it (five example questions an assistant
  can answer once connected), not with the tool list.
- The read-only guarantee is stated in the intro, not buried in a footnote. On
  a site whose security section teaches users to be careful about what they
  connect to their wallet, "this cannot move your funds" is the first question a
  reader will have.
- Connection instructions cover the hosted endpoint (a `claude mcp add` command
  and a generic `mcpServers` JSON block for Claude Desktop, Cursor, and others)
  before the local `npx` route.
- Self-hosting — Docker and the full environment-variable table — is last.

Placed at the top level rather than under `📚 Tutorials` or `💡 Introduction`:
it is a developer/power-user tool, and both of those groups are aimed at users
staking through the app.

### Depth of the tool table

The tool table lists all nine tools but deliberately keeps the borrower-facing
ones (`get_participation`, `get_loan_info`, `get_max_punishment`) at one line
each without further explanation. Explaining validation loans properly belongs
in the validator documentation, and the page already links the architecture and
integration resources for readers who need that depth.

### llms.txt

Per `CLAUDE.md`, `public/llms.txt` is kept in sync when protocol-level facts on
the site change. A public MCP endpoint is exactly the kind of fact an LLM
consuming that file should know, so it was added in three places: the header
link block, a new paragraph plus bullets in `## Technical resources`, and two
entries in `## Important links for LLMs`. `Last reviewed` moved to 2026-07-27.

This is mildly self-referential — `llms.txt` is itself one of the resources the
MCP server serves (`hipo://docs/knowledge`), so an assistant reading it through
the server learns the server exists. That is harmless and arguably useful; it
tells a client connected over stdio that a hosted endpoint is available.

### Considered and not done

- **Sample values in the example response.** The `get_exchange_rate` sample uses
  real numbers captured from the live server during this session (rate
  1.143623345, APY 15.59%), but they are labelled explicitly as a shape rather
  than current values. The alternative — placeholder numbers — reads as fake
  and invites readers to quote them; a dated real sample with a warning is
  more honest. It will go stale, and that is acceptable for an example block.
- **Linking the page from the landing page or FAQ.** Out of scope for a docs
  request, and the audience overlap is small.
- **Documenting `/healthz`.** It exists on the HTTP transport and is used by the
  hosted deployment, but it is deployment plumbing, not something a reader of
  this page needs.
- **A "Node.js 20+" claim vs. the Dockerfile's `node:24`.** The README states
  20+, `package.json` has no `engines` field, and the Docker image pins 24. The
  page repeats the README's 20+. Worth an `engines` field in the MCP repo to
  settle it — noted as a follow-up there, not fixed here.
