## Hipo MCP Server چیست؟

Hipo MCP Server (سرور MCP مربوط به Hipo) سرویسی کوچک و متن‌باز است که به دستیارهای هوش مصنوعی اجازه می‌دهد به داده‌های مرتبط با Hipo، از جمله اطلاعات استیکینگ GRAM و موضوعات دیگر، دسترسی داشته باشند. این سرور با [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) کار می‌کند؛ استانداردی باز برای اتصال کلاینت‌های هوش مصنوعی به داده‌های بیرونی. بنابراین هر کلاینت سازگار با MCP — Claude، Claude Code، Cursor و دیگران — می‌تواند به‌جای حدس زدن از حافظه، مستندات Hipo را جستجو کند و اعداد زندهٔ آنچین را بپرسد.

پس از اتصال، دستیار شما می‌تواند به پرسش‌هایی مانند این‌ها پاسخ دهد:

- _نرخ تبدیل فعلی hGRAM/GRAM چقدر است و چه APY‌ای را نشان می‌دهد؟_
- _همین حالا چقدر GRAM در Hipo استیک شده است؟_
- _دور اعتبارسنجی جاری کی تمام می‌شود و واریز معوق من کی hGRAM ضرب می‌کند؟_
- _موجودی hGRAM این آدرس چقدر است و به GRAM چقدر می‌ارزد؟_
- _برای واریز چه کارمزد شبکه‌ای باید ضمیمه کنم؟_

پاسخ‌ها از گترهای قرارداد هوشمند Hipo روی TON می‌آیند، نه از داده‌های آموزشی مدل؛ بنابراین در لحظهٔ پرسش شما به‌روز هستند.

این سرور کاملاً **فقط‌خواندنی** است. هیچ کلیدی نگه نمی‌دارد، چیزی امضا نمی‌کند و هیچ پیامی به بلاکچین نمی‌فرستد. می‌تواند ببیند، اما هرگز نمی‌تواند دارایی شما را جابه‌جا کند — اتصال آن راهی نیست که کسی بتواند از طرف شما استیک، آن‌استیک یا انتقال انجام دهد.

## اتصال

### سرور میزبانی‌شده (پیشنهادی)

Hipo یک نمونهٔ عمومی را اجرا می‌کند. کلاینت MCP خود را به این نشانی وصل کنید:

```
https://mcp.hipo.finance/mcp
```

در [Claude Code](https://claude.com/product/claude-code) یک دستور کافی است:

```sh
claude mcp add --transport http hipo https://mcp.hipo.finance/mcp
```

این دستور سرور را برای پروژهٔ فعلی ثبت می‌کند. اگر می‌خواهید از همهٔ پروژه‌ها به آن دسترسی داشته باشید، `-s user` را بدهید — `user` اینجا یک کلیدواژهٔ scope است، نه جای‌نگهداری برای نام کاربری خودتان:

```sh
claude mcp add -s user --transport http hipo https://mcp.hipo.finance/mcp
```

در هر دو حالت از دستور استفاده کنید، نه ویرایش دستی فایل پیکربندی: Claude Code سرورهای MCP خود را در پیکربندی مخصوص خودش نگه می‌دارد و بلوک `mcpServers` که در `settings.json` گذاشته شود نادیده گرفته می‌شود. برای اطمینان از اتصال سرور `claude mcp list` را اجرا کنید و پس از آن Claude Code را دوباره راه‌اندازی کنید — سرورها هنگام شروع متصل می‌شوند، بنابراین سروری که تازه افزوده شده در نشستی که از قبل در حال اجراست در دسترس نیست.

کلاینت‌های دیگر (Claude Desktop، Cursor و بیشتر کلاینت‌های دیگر) با یک فایل JSON پیکربندی می‌شوند و ورودی‌ای مانند این می‌گیرند:

```json
{
  "mcpServers": {
    "hipo": {
      "type": "http",
      "url": "https://mcp.hipo.finance/mcp"
    }
  }
}
```

### اجرای محلی

اگر ترجیح می‌دهید سرور را خودتان اجرا کنید، در npm با نام [`@hipo-finance/mcp`](https://www.npmjs.com/package/@hipo-finance/mcp) منتشر شده و با stdio کار می‌کند. این کار به Node.js 20 یا جدیدتر نیاز دارد:

```sh
claude mcp add hipo -- npx -y @hipo-finance/mcp
```

همان توصیه اینجا هم صادق است — آن را با دستور اضافه کنید، نه با ویرایش دستی فایل. برای کلاینت‌های دیگر، ورودی پیکربندی JSON چنین است:

```json
{
  "mcpServers": {
    "hipo": {
      "command": "npx",
      "args": ["-y", "@hipo-finance/mcp"]
    }
  }
}
```

## ابزارها

این‌ها پرسش‌هایی هستند که سرور می‌تواند پاسخ دهد. کلاینت هوش مصنوعی شما خودش ابزار مناسب را انتخاب می‌کند — شما به زبان ساده می‌پرسید.

| ابزار                | چه چیزی برمی‌گرداند                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `get_exchange_rate`  | نرخ فعلی hGRAM↔GRAM، کل GRAM استیک‌شده، عرضهٔ hGRAM و APY اخیر که از به‌روزرسانی‌های آنچین نرخ به دست آمده است                     |
| `get_treasury_state` | جمع‌های خزانه: TVL به GRAM، عرضهٔ hGRAM، واریزها و آن‌استیک‌های در انتظار، مشارکت‌های فعال در دورها، پرچم توقف و پارامترهای حاکمیت |
| `get_round_timing`   | زمان‌بندی دور اعتبارسنجی: مرزهای دور جاری و بعدی، بازهٔ شرکت در انتخابات و اینکه استیک‌ها چه مدت فریز می‌مانند                     |
| `get_fees`           | کارمزد شبکهٔ فعلی برای درخواست‌های واریز، آن‌استیک و وام                                                                           |
| `get_wallet_status`  | موجودی hGRAM یک آدرس مشخص، ارزش آن به GRAM و هر استیک یا آن‌استیک در انتظار                                                        |
| `get_reward_history` | تاریخچهٔ پاداش استیکینگ GRAM یک آدرس مشخص به تفکیک دور، شامل سطح Hipo Club و پاداش‌های HPO                                         |
| `get_participation`  | مشارکت Hipo در یک دور اعتبارسنجی: وضعیت، تعداد وام‌ها، جمع‌ها و زمان آزادسازی استیک                                                |
| `get_loan_info`      | قرارداد وام یک وام‌گیرنده در یک دور: آدرس، وضعیت استقرار، موجودی و طرف‌ها                                                          |
| `get_max_punishment` | بیشترین جریمه‌ای که پروتکل می‌تواند برای یک استیک ولیدیتور مشخص اعمال کند                                                          |

چهار ابزار نخست هیچ ورودی‌ای نیاز ندارند. `get_wallet_status`، `get_reward_history` و `get_loan_info` یک آدرس TON می‌گیرند — آدرس خود مالک یا وام‌گیرنده، نه آدرس کیف پول جتون او — و `get_max_punishment` مقدار استیک را به GRAM می‌گیرد. `get_participation` و `get_loan_info` زمان شروع دور را هم می‌پذیرند، اما اختیاری است: اگر ندهید، دربارهٔ دور جاری گزارش می‌دهند.

هر پاسخ همان یادآوری را با خود دارد که ابزارها دادهٔ زندهٔ پروتکل برمی‌گردانند، نه توصیهٔ مالی: مقادیر در هر دور اعتبارسنجی تغییر می‌کنند و هیچ بازدهی تضمین نمی‌شود.

## منابع مستندات

در کنار داده‌های زنده، سرور اسناد فنی Hipo را به‌صورت منابع MCP در دسترس می‌گذارد که از محل‌های عمومی اصلی‌شان واکشی می‌شوند تا همیشه به‌روز باشند:

| منبع                       | محتوا                                                                     |
| -------------------------- | ------------------------------------------------------------------------- |
| `hipo://docs/overview`     | README مخزن قراردادهای هوشمند: خلاصهٔ پروتکل و آدرس قراردادهای مستقرشده   |
| `hipo://docs/architecture` | قراردادها، ماشین حالت دور اعتبارسنجی و ناوردایی‌های پروتکل                |
| `hipo://docs/integration`  | طرح پیام‌ها و راهنمای یکپارچه‌سازی برای کیف پول‌ها و پروتکل‌های دیگر      |
| `hipo://docs/schema`       | طرح‌های کامل TL-B همهٔ قراردادهای Hipo                                    |
| `hipo://docs/knowledge`    | پایگاه دانش گردآوری‌شدهٔ Hipo ([llms.txt](https://hipo.finance/llms.txt)) |

## نمونه

فراخوانی `get_exchange_rate` یک JSON ساده برمی‌گرداند. اعداد هر دور تغییر می‌کنند، پس این‌ها را یک قالب در نظر بگیرید، نه مقادیر فعلی:

```json
{
  "oneHgramInGram": "1.143623345",
  "oneGramInHgram": "0.874413769",
  "totalCoinsGram": "2501952.200844389",
  "totalTokensHgram": "2187741.455006677",
  "recentApy": "15.59%",
  "apyNote": "APY is derived from the last on-chain rate update (current_rate / previous_rate compounded to a year). Rewards accrue in the exchange rate: hGRAM becomes worth more GRAM over time; there is no separate claim.",
  "disclaimer": "Live protocol data, not financial advice. Values change every validation round and no returns are guaranteed."
}
```

سرور هرگز محاسبات پروتکل را دوباره پیاده‌سازی نمی‌کند. هر عدد بالا از یک گتر قرارداد می‌آید و مخزن قراردادها منبع حقیقت برای آدرس‌های مستقرشده است.

## میزبانی شخصی

سرور با مجوز MIT منتشر شده و در [github.com/HipoFinance/mcp](https://github.com/HipoFinance/mcp) قرار دارد. دو ترنسپورت دارد — `stdio` برای کلاینت‌های محلی و HTTP جریانی برای استقرار میزبانی‌شده — و یک Dockerfile:

```sh
docker build -t hipo-mcp .
docker run -p 3000:3000 -e TONCENTER_API_KEY=... hipo-mcp
```

همهٔ پیکربندی اختیاری است؛ پیش‌فرض‌ها از طریق API عمومی toncenter به شبکهٔ اصلی (مین‌نت) متصل می‌شوند.

| متغیر محیطی                | پیش‌فرض                                | کاربرد                                                                                                                     |
| -------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `HIPO_NETWORK`             | `mainnet`                              | `mainnet` یا `testnet`                                                                                                     |
| `TONCENTER_ENDPOINT`       | `https://toncenter.com/api/v2/jsonRPC` | نقطهٔ پایانی HTTP API شبکهٔ TON                                                                                            |
| `TONCENTER_API_KEY`        | _(هیچ)_                                | کلید API مربوط به toncenter؛ بدون آن محدودیت نرخ عمومی اعمال می‌شود و فراخوانی‌های محدودشده با backoff دوباره تلاش می‌شوند |
| `TONCENTER_API_KEY_FILE`   | _(هیچ)_                                | مسیر فایلی که کلید API را نگه می‌دارد، مانند یک Docker secret؛ بر `TONCENTER_API_KEY` اولویت دارد                          |
| `HIPO_STATE_CACHE_SECONDS` | `5`                                    | مدت کش شدن وضعیت خزانه، زمان‌ها و کارمزدها بین فراخوانی‌های ابزار                                                          |
| `HIPO_DOCS_CACHE_SECONDS`  | `300`                                  | مدت کش شدن منابع مستندات                                                                                                   |
| `HIPO_REWARDS_API_BASE`    | `https://api.hipogang.io`              | URL پایهٔ API پاداش‌های Hipo؛ برای غیرفعال کردن `get_reward_history` آن را خالی بگذارید                                    |
| `PORT` / `HOST`            | `3000` / `0.0.0.0`                     | فقط برای ترنسپورت HTTP                                                                                                     |
