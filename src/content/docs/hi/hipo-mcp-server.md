## Hipo MCP Server क्या है?

Hipo MCP Server एक छोटी, ओपन-सोर्स सेवा है जो AI असिस्टेंट्स को Hipo से जुड़ा डेटा एक्सेस करने देती है, जिसमें GRAM स्टेकिंग और अन्य विषयों की जानकारी शामिल है। यह [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) बोलता है, जो AI क्लाइंट्स को बाहरी डेटा से जोड़ने का एक ओपन स्टैंडर्ड है, ताकि कोई भी MCP-सक्षम क्लाइंट — Claude, Claude Code, Cursor, और अन्य — Hipo के दस्तावेज़ीकरण को देख सके और मेमोरी से अंदाज़ा लगाने के बजाय लाइव ऑन-चेन आँकड़े क्वेरी कर सके।

एक बार कनेक्ट होने पर, आपका असिस्टेंट इस तरह के सवालों के जवाब दे सकता है:

- _मौजूदा hGRAM/GRAM विनिमय दर क्या है, और इसका मतलब कौन-सा APY है?_
- _अभी Hipo में कितना GRAM स्टेक है?_
- _मौजूदा वैलिडेशन राउंड कब खत्म होता है, और मेरी डेफ़र्ड डिपॉज़िट कब hGRAM मिंट करेगी?_
- _इस पते का hGRAM बैलेंस क्या है, और GRAM में इसकी कीमत कितनी है?_
- _डिपॉज़िट के साथ मुझे कितना गैस शुल्क जोड़ना चाहिए?_

जवाब मॉडल के ट्रेनिंग डेटा से नहीं, बल्कि TON पर Hipo के स्मार्ट-कॉन्ट्रैक्ट गेटर्स से आते हैं, इसलिए ये आपके पूछने के समय तक अप-टू-डेट होते हैं।

सर्वर सख्ती से **रीड-ओनली** है। इसके पास कोई की नहीं है, यह कुछ भी साइन नहीं करता, और ब्लॉकचेन को कोई मैसेज नहीं भेजता। यह देख सकता है, लेकिन कभी आपका फंड नहीं हिला सकता — इसे कनेक्ट करना आपकी ओर से स्टेक, अनस्टेक, या ट्रांसफर करने का कोई तरीका नहीं है।

## कनेक्ट करना

### होस्टेड सर्वर (अनुशंसित)

Hipo एक पब्लिक इंस्टेंस चलाता है। अपने MCP क्लाइंट को यहाँ पॉइंट करें:

```
https://mcp.hipo.finance/mcp
```

[Claude Code](https://claude.com/product/claude-code) में, एक कमांड ही काफ़ी है:

```sh
claude mcp add --transport http hipo https://mcp.hipo.finance/mcp
```

यह मौजूदा प्रोजेक्ट के लिए सर्वर रजिस्टर करता है। इसके बजाय हर प्रोजेक्ट से इसे पहुँचने के लिए, `-s user` पास करें — यहाँ `user` एक लिटरल स्कोप कीवर्ड है, आपके अपने यूज़रनेम का प्लेसहोल्डर नहीं:

```sh
claude mcp add -s user --transport http hipo https://mcp.hipo.finance/mcp
```

किसी भी तरह, कॉन्फ़िगरेशन फ़ाइल को हाथ से एडिट करने के बजाय कमांड का इस्तेमाल करें: Claude Code अपने MCP सर्वर्स को अपने कॉन्फ़िग में रखता है, और `settings.json` में डाला गया `mcpServers` ब्लॉक अनदेखा कर दिया जाता है। यह पुष्टि करने के लिए कि सर्वर कनेक्टेड है `claude mcp list` चलाएँ, और उसके बाद Claude Code को रीस्टार्ट करें — सर्वर्स स्टार्टअप पर कनेक्ट होते हैं, इसलिए नया जोड़ा गया सर्वर पहले से चल रहे सेशन में उपलब्ध नहीं होता।

अन्य क्लाइंट्स (Claude Desktop, Cursor, और ज़्यादातर अन्य) एक JSON फ़ाइल से कॉन्फ़िगर होते हैं और इस तरह की एंट्री लेते हैं:

```json
{
  "mcpServers": {
    "hipo": {
      "type": "http",
      "url": "https://mcp.hipo.finance/mcp"
    }
  }
}
```

### इसे लोकली चलाना

अगर आप सर्वर खुद चलाना चाहते हैं, तो यह npm पर [`@hipo-finance/mcp`](https://www.npmjs.com/package/@hipo-finance/mcp) के रूप में प्रकाशित है और stdio बोलता है। इसके लिए Node.js 20 या नया वर्ज़न चाहिए:

```sh
claude mcp add hipo -- npx -y @hipo-finance/mcp
```

यहाँ भी वही सलाह लागू होती है — इसे कमांड से जोड़ें, फ़ाइल हाथ से एडिट करके नहीं। अन्य क्लाइंट्स के लिए, JSON कॉन्फ़िगरेशन एंट्री यह है:

```json
{
  "mcpServers": {
    "hipo": {
      "command": "npx",
      "args": ["-y", "@hipo-finance/mcp"]
    }
  }
}
```

## टूल्स

ये वे सवाल हैं जिनका जवाब सर्वर दे सकता है। आपका AI क्लाइंट खुद सही टूल चुनता है — आप बस सामान्य भाषा में पूछें।

| टूल                  | यह क्या लौटाता है                                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_exchange_rate`  | मौजूदा hGRAM↔GRAM दर, कुल स्टेक किया गया GRAM, hGRAM सप्लाई, और ऑन-चेन दर अपडेट्स से निकाला गया हालिया APY                                     |
| `get_treasury_state` | ट्रेज़री के कुल आँकड़े: GRAM में TVL, hGRAM सप्लाई, पेंडिंग डिपॉज़िट और अनस्टेक, सक्रिय राउंड पार्टिसिपेशन, हॉल्ट फ़्लैग, और गवर्नेंस पैरामीटर |
| `get_round_timing`   | वैलिडेशन राउंड टाइमिंग: मौजूदा और अगले राउंड की सीमाएँ, इलेक्शन पार्टिसिपेशन विंडो, और स्टेक कितनी देर फ्रीज़ रहता है                          |
| `get_fees`           | डिपॉज़िट, अनस्टेक, और लोन रिक्वेस्ट के लिए मौजूदा गैस शुल्क                                                                                    |
| `get_wallet_status`  | दिए गए पते का hGRAM बैलेंस, GRAM में इसकी कीमत, और कोई भी पेंडिंग स्टेक या अनस्टेक                                                             |
| `get_reward_history` | दिए गए पते के प्रति राउंड ऐतिहासिक GRAM स्टेकिंग रिवॉर्ड्स, जिसमें Hipo Club लेवल और HPO रिवॉर्ड्स शामिल हैं                                   |
| `get_participation`  | वैलिडेशन राउंड में Hipo की पार्टिसिपेशन: स्टेट, लोन काउंट्स, कुल, और स्टेक रिलीज़ टाइम                                                         |
| `get_loan_info`      | एक उधारकर्ता का प्रति-राउंड लोन कॉन्ट्रैक्ट: पता, डिप्लॉयमेंट स्टेट, बैलेंस, और पार्टियाँ                                                      |
| `get_max_punishment` | दिए गए वैलिडेटर स्टेक के लिए प्रोटोकॉल जो अधिकतम पनिशमेंट लागू कर सकता है                                                                      |

पहले चार टूल्स को किसी इनपुट की ज़रूरत नहीं। `get_wallet_status`, `get_reward_history`, और `get_loan_info` एक TON पता लेते हैं — मालिक या उधारकर्ता का अपना पता, उनके जेटन वॉलेट का पता नहीं — और `get_max_punishment` GRAM में एक स्टेक राशि लेता है। `get_participation` और `get_loan_info` एक राउंड स्टार्ट टाइम भी स्वीकार करते हैं, लेकिन यह वैकल्पिक है: इसे छोड़ने पर वे मौजूदा राउंड पर रिपोर्ट करते हैं।

हर रिस्पॉन्स में एक ही याद दिलाना शामिल है कि टूल्स लाइव प्रोटोकॉल डेटा लौटाते हैं, वित्तीय सलाह नहीं: मूल्य हर वैलिडेशन राउंड में बदलते हैं और कोई रिटर्न की गारंटी नहीं है।

## दस्तावेज़ीकरण संसाधन

लाइव डेटा के साथ, सर्वर Hipo के तकनीकी दस्तावेज़ों को MCP संसाधनों के रूप में भी उपलब्ध कराता है, जो उनके कैननिकल पब्लिक स्थानों से फ़ेच किए जाते हैं ताकि वे हमेशा अप-टू-डेट रहें:

| संसाधन                     | कंटेंट                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| `hipo://docs/overview`     | स्मार्ट-कॉन्ट्रैक्ट रिपॉज़िटरी का README: प्रोटोकॉल सारांश और डिप्लॉय किए गए कॉन्ट्रैक्ट पते |
| `hipo://docs/architecture` | कॉन्ट्रैक्ट, वैलिडेशन-राउंड स्टेट मशीन, और प्रोटोकॉल इनवेरिएंट्स                             |
| `hipo://docs/integration`  | मैसेज स्कीमा और वॉलेट्स तथा अन्य प्रोटोकॉल के लिए इंटीग्रेशन गाइड                            |
| `hipo://docs/schema`       | सभी Hipo कॉन्ट्रैक्ट के पूरे TL-B स्कीमा                                                     |
| `hipo://docs/knowledge`    | क्यूरेटेड Hipo नॉलेज बेस ([llms.txt](https://hipo.finance/llms.txt))                         |

## उदाहरण

`get_exchange_rate` की एक कॉल प्लेन JSON लौटाती है। संख्याएँ हर राउंड में बदलती हैं, इसलिए इन्हें मौजूदा मूल्यों के बजाय एक ढाँचे के रूप में लें:

```json
{
  "oneHgramInGram": "1.143623345",
  "oneGramInHgram": "0.874413769",
  "totalCoinsGram": "2501952.200844389",
  "totalTokensHgram": "2187741.455006677",
  "recentApy": "15.59%",
  "apyNote": "APY is derived from the last on-chain rate update (current_rate / previous_rate compounded to a year). Rewards accrue in the exchange rate: hGRAM becomes worth more GRAM over time; there is no separate claim.",
  "disclaimer": "Live protocol data, not financial advice. Values change every validation round and no returns are guaranteed."
}
```

सर्वर कभी प्रोटोकॉल गणित को फिर से लागू नहीं करता। ऊपर दी गई हर संख्या एक कॉन्ट्रैक्ट गेटर से आती है, और डिप्लॉय किए गए पतों के लिए कॉन्ट्रैक्ट रिपॉज़िटरी ही सत्य का स्रोत है।

## सेल्फ़-होस्टिंग

सर्वर MIT-लाइसेंस्ड है और [github.com/HipoFinance/mcp](https://github.com/HipoFinance/mcp) पर मौजूद है। यह दो ट्रांसपोर्ट के साथ आता है — लोकल क्लाइंट्स के लिए `stdio` और होस्टेड डिप्लॉयमेंट के लिए स्ट्रीमेबल HTTP — और एक Dockerfile:

```sh
docker build -t hipo-mcp .
docker run -p 3000:3000 -e TONCENTER_API_KEY=... hipo-mcp
```

सारा कॉन्फ़िगरेशन वैकल्पिक है; डिफ़ॉल्ट्स पब्लिक toncenter API के ज़रिए मेननेट को टारगेट करते हैं।

| एनवायरनमेंट वेरिएबल        | डिफ़ॉल्ट                               | उद्देश्य                                                                                                       |
| -------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `HIPO_NETWORK`             | `mainnet`                              | `mainnet` या `testnet`                                                                                         |
| `TONCENTER_ENDPOINT`       | `https://toncenter.com/api/v2/jsonRPC` | TON HTTP API एंडपॉइंट                                                                                          |
| `TONCENTER_API_KEY`        | _(कोई नहीं)_                           | toncenter API की; बिना इसके पब्लिक रेट लिमिट लागू होती है, और रेट-लिमिटेड कॉल्स बैकऑफ़ के साथ रीट्राई होते हैं |
| `TONCENTER_API_KEY_FILE`   | _(कोई नहीं)_                           | API की रखने वाली फ़ाइल का पाथ, जैसे कि Docker सीक्रेट; यह `TONCENTER_API_KEY` से पहले लागू होता है             |
| `HIPO_STATE_CACHE_SECONDS` | `5`                                    | टूल कॉल्स के बीच ट्रेज़री स्टेट, टाइम्स, और शुल्क कितनी देर कैश किए जाते हैं                                   |
| `HIPO_DOCS_CACHE_SECONDS`  | `300`                                  | दस्तावेज़ीकरण संसाधन कितनी देर कैश किए जाते हैं                                                                |
| `HIPO_REWARDS_API_BASE`    | `https://api.hipogang.io`              | Hipo रिवॉर्ड्स API का बेस URL; `get_reward_history` को अक्षम करने के लिए इसे खाली सेट करें                     |
| `PORT` / `HOST`            | `3000` / `0.0.0.0`                     | केवल HTTP ट्रांसपोर्ट                                                                                          |
