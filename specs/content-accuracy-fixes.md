# Content accuracy fixes — FAQ, HPO page, docs

**Status:** implemented (2026-08-23) except D42, B4 and B14, held pending open questions 3 and 4; the F5 browser check is recorded as verified by the user, the preview click-through is still open

## Goal

Remove every factual error, cross-page contradiction and stale-as-live statement that the 2026-08-23 content
review found in the English FAQ, the HPO page and the docs, and ship the matching fa/ru/hi updates in the same
batch. Copy edits only: no page is added, merged, deleted or moved, and no sidebar or route changes. After this
change every claim on the site is either verifiable from the contracts, the audits repo, the docs' own dated
records, or is deferred to live data (`/stats/`, the app, the HPO page) as `public/llms.txt` requires.

## Context

The review (session scratchpad, `content-review-2026-08-23.md`) read the 105 English prose files, the 40
English docs pages and the `en` catalogs and pulled live protocol values through the Hipo MCP server. Every
file:line below was re-opened and confirmed before this spec was written. What is wrong, grouped:

- **Contradictions between pages.** The minimum stake is answered four different ways ("as little as 1 GRAM",
  "even less than 1 GRAM", "any amount"); the FAQ says two audits while the landing page and `hpo.json` say
  four; the reward cadence is stated three incompatible ways across `hipo-rewards.md`, `profit-sharing.md` and
  `hipo-club.md`; HPO is a "decision-making", "revenue-sharing" or "governance and profit-sharing" token
  depending on the page (`src/i18n/GLOSSARY.md` already fixes the last one as canonical).
- **Retired programmes presented as live.** The HPO page and `hpo-faq/07` recruit for Hipo Gang, which ended
  2025-02-25; `hipo-club.md` teaches the pre-Season-4 model (6 levels, claim discounts, sell allowances,
  72-hour claiming window) in its body and retracts it in a footnote; `tvl-milestone-rewards.md` and
  `hipo-incentive-programs.md` advertise 2M–5M GRAM TVL milestones that were never run, at a TVL of 8.44M.
- **`llms.txt` rule violations.** "the highest staking rewards in the TON ecosystem", "the most optimized APY
  possible", "highest record of TPS among all blockchains" (superlatives with no live data on the page);
  "~20% APY in TON" and "up to 43.7% total APY" (hardcoded APY; live recent APY ≈ 16%); "Unstake Anytime …
  at any time" and "Freedom to Unstake … whenever you choose" (unconditional-withdrawal claims);
  "capitalize on price movements … speculate … maximize returns" and "Start Your Investment Now"
  (investment advice/framing).
- **Wrong facts.** "TON is backed by Telegram Messenger" (Telegram withdrew in 2020); "extensive testing on a
  dedicated testnet" (the contracts are tested with Blueprint, and website testnet support was removed
  2026-08-10); `Landing.astro:22` credits the March-2024 report to "Ender Ting" while its own href points at
  `#2024-03-programcrafter-hipo-audit-report` — the audits repo README lists the author as **ProgramCrafter**;
  Hipo Fund's April table sums to $129,726 against a stated $186,963.96.
- **Meaning-changing typos and defects.** "Hipo Cub" for Hipo Club (twice), "Powerd", the unconverted entity
  `burne&#x64;`, the "How We Use the Information" heading glued to the end of a paragraph in the privacy
  policy, two `title=` attributes that name videos the embeds are not, and DEX links that preselect the
  pre-rename `hTON` symbol in the wrong swap direction.

**The i18n gate constrains everything.** fa, ru and hi are `indexed` (released). `node scripts/check-i18n.mjs`
runs as `prebuild`: a released locale missing any catalog key, prose file, doc page or sidebar label **fails
the build**. Editing an English string or doc changes its sha1 in `src/i18n/<locale>/meta.json`, which makes the
translation _stale_ (a warning, not an error) until the twin is updated and `--update-hashes <locale>` is run.
Renaming a catalog key (this spec renames three) makes the old locale entries _extra_ (warning) and the new
ones _missing_ (**error**) until all four catalogs are edited; `--update-hashes` rebuilds `meta.json` from the
English key set, so orphans are pruned automatically. `public/llms.txt` is English-only for all locales and has
no twin.

Live values pulled 2026-08-23 for the wording below (never hardcoded in copy): governance fee 0.00%, TVL
8,442,725 GRAM, deposit gas prepayment 0.0088 GRAM, unstake 0.0140 GRAM (both "on the order of a hundredth of
a GRAM"), round ≈ 18 h, freeze ≈ 9 h.

## Approach

One batch, one branch, one commit series:

1. **English first** — apply §§A–F below. Every replacement sentence is written out; the implementer copies it,
   does not re-derive it.
2. **Then the twins** — §G: for exactly the files touched in §§A–F, update `fa`, `ru`, `hi` (LLM-drafted from
   the new English plus `src/i18n/GLOSSARY.md`, per `specs/multi-language-site.md` decision 5), then
   `node scripts/check-i18n.mjs --update-hashes <locale>` for each. Do not touch untouched items.
3. **Keep the neighbours consistent** — `public/llms.txt`, `src/components/Landing.astro` and the `en` catalogs
   carry the same canonical sentences (§E); the app-shell prose is already correct on the minimum stake and is
   the source we copy from, not a target to change (§C).
4. **No restructuring.** No file is created, deleted, renamed or moved; no headings are re-levelled; no FAQ
   items are merged or cut. Where a fix removes a claim, the surrounding structure stays as it is.

  The 0.1 GRAM figure is `feeStake`/`feeUnstake` in `@hipo-finance/sdk` (also `app.multisig.stakeInstructionsNoAmount`)
  — update together with `staking/can-i-stake-with-a-multisig-or-cold-wallet.md` (no HTML comment there: the prose
  collection has no precedent for HTML comments). Location: A5.
- **CS-8 — governance fee.** "a governance fee on validation rewards, set by the [Hipo DAO](/docs/dao/),
  currently 0%". Locations: A4, A6.

## Risks & rollback

- **Baked-in numbers in images.** `/docs/images/introduction-hipo-rewards-1.jpg` is the diagram that the
  "~20% APY / 43.7%" bullets describe, and it very likely carries the same figures. Fixing the text does not
  fix the image — check it, and if it does, either replace it or drop the `<figure>` in the same commit.
  Same check for `hipo-fund-1.jpg`.
- **Translation drift.** The twins are LLM-drafted and land unreviewed (`reviewed: false`). fa/ru/hi are
  `indexed`, not `public`, so they are crawler-visible but carry no language UI; a wrong nuance is a warning-level
  risk, not a user-facing regression, and is cleaned up in the next native review pass.
- **Key renames.** Three renames (`hpo.utility.gang.*`, `hpo.utility.offers.*`, `landing.audits.enderTingDate`)
  each touch four catalogs plus one `.astro` file. A missed catalog fails the build — which is the desired
  behaviour, and is caught before push by `npm run build`.
- **DEX URL forms.** F5 changes the app's swap links; a wrong URL form silently opens the venue with nothing
  preselected (annoying) or, worse, a look-alike token (harmful). Mitigation: address-based URLs and a browser
  check of every link before commit (Open question 8); the pool links (`*PoolUrl`) are already address-based.
- **Rollback**: pure content, no schema or route change. `git revert` of the batch restores the previous
  wording; nothing else depends on these strings.
